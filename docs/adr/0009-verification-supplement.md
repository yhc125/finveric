# 0009. 기존 판매 시스템을 보완하는 기록 검증으로 범위를 정한다

2026-11-24 · 결정됨 · [0006](0006-seller-console-and-single-web-app.md)의 판매 시스템 대체 전제를 바꾼다. 사용자·화면 구성은 유지한다.

## 맥락과 결정

최종발표를 준비하며 교수님 피드백을 반영해 서비스 범위를 명확히 했다. 0006은 판매사가 판매 절차 시스템을 직접 운영하는 대신 FINVERIC을 쓴다고 설명했다. 기존 시스템 전체를 대체하면 판매 업무와 원문 보관의 책임까지 확장되고, 현재 구현한 기록 검증의 범위를 넘어선다.

기존 판매 관리·원문 보관 체계에 기록 검증 기능을 연결한다. 고객별 민감한 원문은 판매사가 관리하고 공동 원장은 검증 정보를 보관한다. 개인정보가 없는 공통 진단 기준과 상품 설명서 원문은 독립 검증에 필요하므로 v5 이벤트에 유지한다. 모든 원문을 원장에서 제거하는 대안은 기존 기준·설명서 검증과 시연을 바꾸므로 선택하지 않는다.

MVP의 진단 API와 오프체인 저장소는 판매사 연동의 예시다. 실제 원문 저장소 연동, 허가형 블록체인 구축, 기관별 독립 키 관리는 상용화 단계로 남긴다. 현재 키를 한 API가 관리한다는 한계를 숨기지 않는다. 업무 효율 비교 실험은 별도 작업이다.

누적 3회차 승인 조건은 법정 횟수 기준이 아닌 FINVERIC 자체 내부통제 정책이다. 기존 회로·원장·승인 서명 형식을 유지한다. 사유·검토 근거는 선택형 코드로 오프체인에만 추가하며, 원장으로 진실성이나 변경 방지를 증명한다고 주장하지 않는다. 저장 위치와 공개 범위의 기준 문서는 [PRD](../prd.md#원장-zkp-원본의-역할)다.
