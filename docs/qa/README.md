# QA 안내와 기록

2026-11-13 · 시연 전 수동 점검 방법, 체크리스트, 날짜별 기록

자동 검사(`npm test`, `npm run contracts:test`, `npm run build`)는 커밋 전에 로컬에서 돌린다. QA는 사람이 화면으로 시연 흐름을 따라가며 확인하는 점검이다. 실행 방법은 [실행과 시연](../runbook.md), 기대 결과의 기준은 [PRD 완료 기준](../prd.md#완료-기준)이다.

## 방법

- 차수마다 환경과 커밋을 고정한다. 환경은 `Docker 로컬(Anvil)` 또는 `Vercel + Sepolia`다.
- [체크리스트](#체크리스트)를 위에서부터 진행한다.
- 실패한 항목은 [QA 이슈 템플릿](../../.github/ISSUE_TEMPLATE/qa.md)을 써서 GitHub 이슈로 남긴다. 차수 기록에 이슈 링크를 붙인다.
- 고친 이슈는 다음 차수에서 다시 확인한다. 다시 확인한 결과도 그 차수 기록에 적는다.

| 심각도 | 기준 |
| --- | --- |
| 치명 | 시연이 멈춘다. 판정·검증 결과가 틀린다. 원장이 받아야 할 기록을 거절하거나, 거절해야 할 기록을 받는다. |
| 주요 | 흐름은 끝까지 가지만 틀린 표시·문구가 있다. 우회해야 한다. |
| 경미 | 문구, 정렬, 스타일 문제다. 시연에 영향이 없다. |

## 체크리스트

### 공통

- [ ] 진입 화면에서 원장 상태가 `정상`이고 원장 버전이 `v5`다.
- [ ] 390px 너비에서 가로 스크롤이 생기지 않는다(표 안의 스크롤은 허용).
- [ ] 브라우저 콘솔에 오류가 없다.
- [ ] 증권사 앱 예시(고객 화면)에 블록 번호와 해시가 기본으로 보이지 않는다.
- [ ] 화면 문구에 `시연`, `모의`, `테스트용`이 없다. 원장에 등록한 기준·상품 이름은 예외다. client와 auditor의 **처음 화면**이 진입 화면으로 간다.
- [ ] 판매사 콘솔 사이드바 하단의 **증권사 앱 예시**와 **API 문서**가 새 탭으로 열린다. API 문서는 접근 코드 없이 열린다.

### 시연 흐름

[실행과 시연](../runbook.md#발표-순서)의 발표 순서와 시연 답변을 그대로 따른다.

| 단계 | 확인할 결과 |
| --- | --- |
| 1. 기준 등록 | 상품 3종과 진단 기준 v1이 등록된다. 감독기관 기준 감사에서 해시가 일치한다. |
| 2. 진단과 중단 | 1회차가 위험중립형이다. 가입을 중단해도 회차가 판매·검토에 남는다. |
| 3. 다시 시작 | 2회차 적극투자형, 3회차 공격투자형이다. 3회차 권유 가능 위험등급이 2등급까지다. 관리자 승인 안내가 나온다. |
| 4. 부적합 확인과 설명 | 권유하지 않는다는 안내와 판매대상 고객군이 나온다. 추가 위험 확인, 설명 카드 5장, 녹취 동의 뒤 청약 단계가 승인을 기다린다. |
| 5. 관리자 승인과 청약 | 콘솔에서 승인하면 증권사 앱 예시 탭이 새로 고침 없이 **청약하기**를 연다. 위험 신호에 재진단 반복과 결과 상승이 있다. 청약이 성공한다. |
| 6. 숙려와 확정 | 숙려 중에는 버튼이 막혀 있다. 60초 뒤 **확인하고 가입하기**가 열리고, 누르면 확정되고 증명서가 나온다. |
| 7. 사후 변경 시도(선택) | API 호출에 원장이 `InvalidAttempt`로 거절한다. 온체인 처리에 거절 이유가 남는다. |
| 8. 고객 검증 | 증명서 번호로 `일치`, 답변 하나를 직접 바꾼 원본으로 `불일치`(원본 답변 대조)다. 없는 번호는 `기록 없음`이다. |
| 9. 감독기관 조회 | 분쟁 조회에서 원장만, 판매사 제출 자료, 파일 대조가 된다. 대시보드, 위험 신호, 보고서(JSON·CSV)가 원장 기록과 맞는다. |

### 화면별 추가 항목

- [ ] 진단 기준: 편집기가 오류를 바로 표시한다. 미리보기 결과가 판정과 같다. 새 버전을 등록하면 다음 진단부터 그 버전을 쓴다.
- [ ] 상품 관리: 새 버전을 등록하면 증권사 앱 예시가 최신 버전을 쓴다. 고난도 상품은 이름 앞에 `고난도 금융투자상품`이 붙는다.
- [ ] 적합한 상품(ELB): 녹취·숙려 없이 확정된다.
- [ ] 청약 철회: 숙려 중에 철회하면 상태가 철회로 바뀐다.
- [ ] API 키: 발급하면 키 원문이 한 번만 보인다. 그 키로 `판매 채널 연동` API를 부르면 통과하고, 판매사 콘솔 API는 403이다. 폐기하면 401이다. 목록에 마지막 사용 시각이 나온다.
- [ ] 증권사 앱 예시 단계 화면: 단계가 바뀌면 화면 맨 위로 가고 새 단계 제목에 초점이 간다. 단계마다 주요 버튼이 하나다. 처리 중에는 버튼이 막히고 진행 문구가 나온다.
- [ ] 증권사 앱 예시 이어 하기: 설명 카드 중간에 다른 탭에 다녀와도 같은 단계로 돌아온다. 다른 상품의 청약 전 가입이 있으면 새 가입 전에 확인 창이 나온다.
- [ ] 기준·상품 감사: 버전 사이의 차이가 맞게 표시된다.
