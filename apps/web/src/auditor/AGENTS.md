# auditor 페이지 작업 규칙

감독기관(B2G)이 쓰는 화면이다. `/auditor/` 아래에서 실행한다. 화면을 고치기 전에 루트 [DESIGN.md](../../../../DESIGN.md)를 읽는다. 화면 범위는 [PRD 화면 구성](../../../../docs/prd.md#화면-구성)을 따른다.

화면 문구는 합니다체로 쓴다. 날짜와 시각은 `src/shared`의 `dateTime`으로 쓴다.

## 경로

| 경로        | 화면      | 내용                                                                                    |
| ----------- | --------- | --------------------------------------------------------------------------------------- |
| `/`         | 대시보드  | 판매 건 상태별 수, 진단 회차, 고객 가명 ID 수, 상품·위험등급별 분포, 재진단·부적합 비율 |
| `/disputes` | 분쟁 조회 | `?sale=`은 판매 건 대조, `?customer=`는 고객 가명 ID의 진단 회차와 판매 건이다          |
| `/rules`    | 기준 감사 | 기준 버전, 원문으로 다시 계산한 기준 해시, 원문, 버전 사이의 차이(`?version=&base=`)    |
| `/products` | 상품 감사 | 상품별 설명서 버전, 지문·속성 대조, 원문, 버전 사이의 차이(`?product=&version=&base=`)  |
| `/signals`  | 위험 신호 | 신호 5종과 종류별 필터(`?kind=`). 판매 건과 고객은 분쟁 조회로 연다                     |
| `/report`   | 보고서    | 가입 확정 건의 일괄 대조와 JSON·CSV 내려받기                                            |

- 이전 주소 `/?sale=…`, `/?source=file`, `/report?sale=…`은 같은 쿼리로 `/disputes`에 보낸다. client의 이전 주소 전환과 공유한 링크가 쓴다.
- 브랜드와 "처음 화면" 항목은 진입 화면(`/`)으로 간다(`Shell`의 `entryHref`). 판매사 콘솔로 가는 메뉴는 두지 않는다.

## 데이터

| 자료                                | 출처                                                                                     |
| ----------------------------------- | ---------------------------------------------------------------------------------------- |
| 기준, 상품 버전, 진단 회차, 판매 건 | `readLedger`(지정 RPC). 먼저 `requireDeployment`로 체인과 코드를 확인한다                |
| 판매 건 대조                        | `verifySale`(`voice: "hapnida"`). 원장만, 판매사 제출 자료, 파일 중 하나와 함께 대조한다 |
| 판매사 제출 자료(증명서·원본)       | `GET /api/sales/:id/export/receipt`, `/original`. 분쟁 조회에서만 받는다                 |
| 위험 신호                           | `computeSignals`(판매사 콘솔과 같은 함수)                                                |
| 검증 설정                           | 사이트 루트의 `/deployment.json`(`useDeployment`). 원장 v5만 읽는다                      |

- 이 페이지는 판매사 API에 POST를 보내지 않는다. 기록을 바꾸는 기능을 넣지 않는다.
- 판정, 해시, 신호는 `packages/core`를 쓴다. 화면에서 다시 구현하지 않는다. 버전 사이의 차이(`diff.ts`)와 보고서 형식(`report.ts`)만 여기에 둔다.
- 원장은 `useLedger`가 한 번 읽고 모든 화면이 함께 쓴다. 분쟁 조회와 보고서는 대조 직전에 다시 읽는다.
- 분쟁 조회는 원장만 대조한 결과와 제출 자료를 넣은 결과를 함께 만든다. "원장 기록과 가입 조건"과 "제출 자료 대조"를 따로 표시한다.
- 결과는 `일치`, `불일치`, `기록 없음`만 쓴다. 불일치는 주의 색, 아이콘, 글자로 함께 표시한다.
- 블록 번호와 거래 해시는 "블록·거래 보기"나 접은 영역에 둔다. 판매 ID, 해시, 주소는 `code`(identifier 글꼴)로 쓴다.
- 고객 번호와 개인정보는 원장에 없다. 화면에도 표시하지 않는다.

## 코드

| 파일                 | 내용                                             |
| -------------------- | ------------------------------------------------ |
| `App.tsx`            | 메뉴, 경로, 이전 주소 전환, 진입 화면 링크       |
| `useLedger.ts`       | 원장 읽기와 다시 읽기                            |
| `format.ts`          | 표시 문구, 상품·기준 이름 찾기, 화면 경로        |
| `diff.ts`            | 진단 기준·설명서 버전 사이의 차이                |
| `report.ts`          | 보고서 생성(`verifySale`), CSV, 텍스트 내려받기  |
| `components.tsx`     | 원장 조회 도구, 대기·오류 표시, 비율 줄(`Ratio`) |
| `ChangeList.tsx`     | 차이 목록                                        |
| `auditor.module.css` | 감독기관 화면 스타일                             |
| `screens/`           | 화면 6개                                         |

- 보고서는 브라우저가 만든다. 파일에 조회한 원장과 자료 출처를 넣는다. 개별 보고서는 화면의 대조 결과를 쓰며 제출 파일 원문을 담지 않는다.
- CSV는 Excel이 한글을 읽도록 BOM을 붙인다. 수식으로 읽히는 첫 글자(`=`, `+`, `-`, `@`)는 막는다.
